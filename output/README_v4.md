# FORM Subdivision Studio 宣传片(第四版)

约 75 秒的 16:9 宣传片。前约 28 秒是代码绘制的问题介绍(开场、周期痛点、重复的前期活儿、两派建模),
网站在“所以我做了这个网站”那一句登场,之后全部是对线上网站 https://form-cc-studio.netlify.app/ 的逐帧真实录屏。
没有使用任何 AI 生成的图像或视频。

## 先说清楚的四件事

1. **配音是 AI 合成语音,不是真人录音。** 用的是微软 Edge 朗读功能的在线神经语音(默认 `zh-CN-YunxiNeural`,语速 +8%)。
   这个接口不是微软对外授权的商用渠道;正式发布建议换成你自己的录音(见下文),或有授权的语音服务。
   合成时为了保证读音,把“车长”写成了同音的“车常”、把“SubD”写成了“Sub D”(只影响发音,字幕仍是原文)。
2. **音乐和音效由代码合成**(`pipeline/audio.mjs`),不是成品曲目。
3. **这个在线平台只保留文本文件。** mp4、png、jpg 不会随项目保存,所以页面里的视频是切成 base64 文本分片
   (`src/generated/`)内嵌的。要拿到 1920×1080 · 60 帧的主版本文件,请在自己的电脑上重建。
4. **录制时隐藏了一个元素**:托管平台注入的 “Powered by Netlify” 浮标(`#nl-badge-frame`,不在产品源码里)。
   界面的文字、数值、布局没有任何改动。想保留它,把 `pipeline/lib/studio.mjs` 里 `openSession` 的 `hideBadge` 改成 `false`。

### 调参数值是怎么选的(第三版)

上一版为了让变化显眼,把数值拉得太猛(轮眉半径 450、方圆度 75、腰线高度 1070、车宽 2000),车走了形。
这一版先用截图比对了三组方案,选定的目标写在 `pipeline/record.mjs` 顶部(`DIMS`、`FRONT`、`RIM`、`GAP`、`TUNE`):

| 参数 | 基础方案「运动溜背轿车」 | 调整后 | 用意 |
| --- | --- | --- | --- |
| 车长 / 车宽 | 4698 / 1840 | 4878 / 1920 | 稍长稍宽 |
| 轴距 | 2808 | 2958 | 轴距拉长 |
| 前轮中心距车头 | 1051(车长拉长后) | 899 | 前轮前移,前悬变短 |
| 轮辋直径 | 18 in | 20 in | 轮子更大 |
| 最小轮胎间隙 / 轮眉半径 | 35 / 395 | 20 / 380 | 轮眉贴住轮胎 |
| 腰线高度 / 前后升降 | 970 / 45 | 1000 / 70 | 腰线略高、略上扬 |
| 侧围趋势 / 车门侧面凹塑 / 曲面硬朗度 | 55 / 45 / 58 | 68 / 58 / 70 | 型面小幅收紧 |
| 前脸格栅 | 无格栅整面 | 有格栅开口 | 前脸多一处细节 |

“更协调”是对着截图做的主观判断;想换一组数值,改这几个常量后重新录制即可。
调参分两段录制(R3 和 R6 并行),R6 开录前会按同样的顺序把参数预置到 R3 结束时的档位,这一步不入镜。

### 导出镜头的推近与按压(第三版)

录制时用 `pressOn()` 记下「导出模型」和「细分工程包（推荐）」两次按下的时刻和位置(`raw/R8.meta.json` 里的 `press` 事件),
合成页据此把镜头推近到按钮(约 2 倍)。按下的瞬间画面整体下沉约 3.5% 再弹回,按钮外圈一道亮框向内收、松开后向外扩散。
这是叠在录屏上面的包装,不改动界面本身;网站按钮自己的按下状态是下移 1 像素,录屏里也在。

## 一键重建

```bash
bash pipeline/setup.sh     # Debian / Ubuntu:ffmpeg、字体、Playwright Chromium、edge-tts
node build.mjs all         # 录制 → 口播合成 → 时间表 → 混音 → 渲染 → 封装 → 封面 → 抽帧 → 内嵌到页面
npm run build              # 生成 dist/index.html(成片页面)
```

只重跑其中几步:`node build.mjs schedule audio web master sheets embed`(不重新录制、不重新合成语音)。

| 环境变量 | 说明 |
| --- | --- |
| `PROMO_WORK` | 帧序列等中间文件目录,默认项目内 `.work/` |
| `PROMO_DSF` | 录制像素比。默认 `1`(按 1440×810 录制);设 `1.3333` 录成 1920×1080,无显卡时慢一倍以上 |
| `PROMO_GPU=1` | 有显卡的机器走真实 GPU;默认用 SwiftShader 软件渲染 WebGL |
| `PROMO_VOICE` / `PROMO_VOICE_RATE` | 合成语音的音色与语速,默认 `zh-CN-YunxiNeural` / `+8%` |
| `WEB_CRF` | 页面内嵌版的压缩质量,默认 29 |

无显卡的 2 核机器上实测:两路并行录制约 12 分钟,720p 渲染约 2.5 分钟,1080p60 渲染约 10 分钟。

## 换成你自己的录音

把录音放到 `assets/audio/`,文件名对应 `pipeline/vo_lines.json` 里的 id:

| 文件 | 内容 |
| --- | --- |
| `s1.wav` | 做汽车造型,第一版数据,再也不用从零开始了。 |
| `s2.wav` | 汽车前期方案做 SubD 建模,最快也要一天一版。但这种强度撑不了几次,正常要三到五天。 |
| `s3.wav` | 而且很大一部分时间,都浪费在前期那些重复的活儿上:定车的尺寸,抓整车的趋势。 |
| `s4.wav` | SubD 建模大致分两派:一派从方盒子开始推拉,一派用拼接法,先做轮眉,再做腰线。 |
| `s5a.wav` | 所以我做了这个网站。 |
| `s5b.wav` | 里面有常用的标准车型, |
| `s5c.wav` | 输入车长、车宽、轴距、轮眉尺寸,车身实时变形。 |
| `s5d.wav` | 再调整整体的断面感觉,就能得到一版体块上差不多的方案。 |
| `s6.wav` | 然后直接导入 Alias 或犀牛,继续做细节。 |
| `s7.wav` | 一键导出 SubD,链接就在这里,快来试吧! |

S5 分成四个文件,是为了让每一小句落在对应的画面上。然后执行:

```bash
node build.mjs schedule audio web master sheets embed && npm run build
```

- 有录音的段落自动替换合成语音,可以只换其中几段。
- 镜头时长 = max(口播时长 + 留白, 已录素材长度),并对齐到 120 BPM 的拍点;素材放完后画面缓慢推近,不会出现静帧。
- 口播处音乐自动压低 11 dB(起 0.10 秒,落 0.35 秒),音效压低约 6 dB。
- 录音没有逐词时间戳,同一段里几条字幕的切换时间按字数比例分配;合成语音则用真实的逐词时间。
- 开头三张大字卡、痛点、两派动画的节点都跟着口播走:换了录音,动画节点会一起移动。

## 字幕

字幕在画面下方单独的字幕条里(高 132 像素),浏览器窗口、动画和包装文字只占上方 948 像素,所以字幕不会压住任何界面。
文字取自口播稿原文,按逗号和句号拆成单行短句,省略了行尾标点。

## 音乐与响度

- 音乐是代码合成的(Am–F–C–G,120 BPM),段落跟着镜头走:问题介绍用半拍速,网站登场时进完整律动,导出时抽掉鼓,结尾再回来。
- 点击声对应录屏里真实的鼠标按下时刻。
- **还没有实现**读取 `assets/music/track.mp3` 和自动检测 BPM。要用成品曲目,需要可商用授权的文件,并在 `pipeline/audio.mjs` 里接入。
- 响度:先调增益再过限幅器,实测后微调到 −14 LUFS;混音的真峰值压在约 −2.5 dBTP,AAC 编码后约 −1.3 dBTP。
- `WORK/audio/report.json` 里有一项 `voiceOverBackgroundDb`,是口播区间里人声比背景(音乐 + 音效)高出的分贝数,用来在听不到声音的情况下把关。

## 录制方式

- `pipeline/lib/studio.mjs` 用 Playwright 的 clock 在导航前接管页面时间。录制时页面时间冻结,每个视频帧推进 16 ms,
  恰好触发一次 `requestAnimationFrame`,页面渲染完才截图;CSS 动画用 Web Animations API 逐帧步进。
- 光标是叠在页面最上层的覆盖层(`pointer-events: none`),与真实鼠标事件同步。
- 数值气泡里的参数名、数值、单位,是录制时逐帧从真实输入框读回的(存在 `raw/*.meta.json`)。
- 网站对参数有 60 ms 防抖:数值停住后模型才重算。所以滑块是“拖一段停一下”。
- 两路录制并行:会话 B 开录前(不入镜)把车调到会话 A 结束时的数值,两段的车身状态才接得上。
- 页面 JS 时间每帧走 16 ms、视频按 60 帧播放,由定时器决定的时长被拉长约 4%。

## 目录结构

```
build.mjs                 一键重建
pipeline/
  setup.sh                环境准备
  vo_lines.json           口播分段、字幕拆行、高亮词
  tts.py                  口播合成(edge-tts)
  lib/studio.mjs          启动浏览器、接管时钟、光标层、逐帧截图、编码
  lib/actions.mjs         点击、悬停、拖拽旋转、右键平移、滚轮缩放、拖滑块
  record.mjs              录制编排(名称取自 src/data/stage0.json)
  schedule.mjs            时间表:镜头起止、口播位置、字幕、动画节点、音效事件
  timeline/index.html     合成页,提供 seek(t)
  render.mjs              逐帧渲染
  audio.mjs               音乐、音效、口播混音与响度
  cover.html              封面
  embed.mjs               把成片和图片转成 base64 文本分片写进 src/generated/
  stage0_probe.mjs        真实界面清单探测
raw/                      录屏片段与逐帧元数据
output/                   成片、字幕、封面、本说明
src/                      成片页面(React),src/generated/ 是内嵌的视频与图片
```
